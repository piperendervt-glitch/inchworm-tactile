# 設計依頼: 仮想シャクトリムシの「触覚→視覚変換」操作システム（Quest 3）

## 1. 依頼の要旨

仮想空間上のシャクトリムシ型モデルを、**歩行映像を一切見ずに**、腹側・頭部の触覚グリッドの濃淡だけを Quest 3 の HMD に表示して人間が操作するシステムを設計してください。

このシステムは、後段で NCA（ニューラルセルオートマトン）に歩行を学習させるための「人間による操作ログ収集装置」でもあります。したがって、触覚フレームと操作入力を同期して記録する機能を最初から含めてください。

## 2. 背景と方針（変更不可）

- 最終目標はこのシャクトリムシを現実世界のロボットにすること。仮想空間側の触覚は「理想の圧力」ではなく、これから自作する実機センサ（反射型 光ファイバー TacTip、ピッチ 15 mm）の特性に合わせる
- 制御思想は「考える筋肉」: 節ごとに 触覚セル＋アクチュエータ＋局所則 を持つ分散構造。中央の脳を置かない。人間操作段階でもこの構造を崩さない（人間は各節の目標角を与えるだけ）
- 感覚は触覚のみ。匂い・視覚・位置情報など別チャネルは足さない
- 意図的に小さく作る。セル数・自由度・チャネル数を増やして賢くする方向には行かない

## 3. 身体仕様

| 項目 | 値（初期案） |
|---|---|
| 節数 | 5 |
| 節ごとの自由度 | 上下曲げ 1（ピッチ） |
| 頭部の追加自由度 | 左右曲げ 1（ヨー） |
| 腹側触覚グリッド | 節ごと 3×3、体全体で 3×15 |
| 頭部前面触覚グリッド | 3×3 |
| セルの物理ピッチ | 15 mm（実機と同一） |
| 左右転倒 | しない（前提。足裏は幅広の平面としてモデル化） |

## 4. 触覚セルの応答モデル（実機準拠）

セルの値は「圧力」ではなく**輝度**として扱う。反射型センサの特性を再現すること。

- 無荷重でも底の輝度がある（ゼロにならない）
- ピンが沈むほど明るくなる非線形（飽和あり）
- フレームごとのノイズ
- 1〜2 フレームの遅延
- 上記のパラメータはすべて外部から調整可能にし、実機の卓上テスト結果で後から差し替えられるようにする
- 更新周期は 30 Hz 固定（実機と揃える）

## 5. 環境

仮想空間には以下の 3 種を配置する。すべて「触れたときの圧力パターン」だけで区別できること。

| 種別 | 物理的な性質 | 触覚グリッドに出る痕跡 |
|---|---|---|
| 地面 | 硬い・平ら | 均一な輝度 |
| 餌 | 柔らかい（スポンジ相当） | 押した分だけ沈み、低く広い輝度分布 |
| 害を及ぼす物質 | 硬く粗い（紙やすり相当） | 細かい高低差による縞・まだら模様 |
| 障害物 | 硬い段差 | 頭部前面グリッドが押される。腹側では前後で輝度が急変 |

材質は「硬さ」「表面の粗さ」の 2 パラメータで定義し、この 2 つから触覚パターンを生成する。実物（スポンジ・紙やすり・段差）で後から校正できる形にすること。

### HP
- 常時わずかに減少
- 餌に頭部を一定時間押し当てると摂食（+HP）、餌は消滅
- 害に触れている間は毎フレーム −HP（腹側・頭部どちらでも）
- 0 で終了
- 人間操作段階では HP は表示してよい（ただし触覚グリッドとは別枠で、小さく）

## 6. 操作系（Quest 3 コントローラ）

- 各節の上下曲げ目標角、頭部の左右曲げ目標角を、コントローラの姿勢・スティック・トリガーに割り当てる
- 割り当ては複数案を提示してほしい。例:
  - 案 A: 左スティックで「注目する節」を選び、右スティック上下で目標角
  - 案 B: 左右コントローラの傾き（姿勢）で前半／後半の節群をまとめて曲げる
  - 案 C: トリガー量で「収縮度」1 パラメータだけを与え、節ごとの角度は固定の波形で配分する（最も低次元）
- どの案でも、記録される操作入力は「各節の目標角の時系列」に正規化して保存する（NCA の教師データにするため）

## 7. 表示（HMD）

- 主表示: 腹側 3×15 と頭部前面 3×3 の触覚グリッドをグレースケールの矩形として視野中央に表示。歩行映像・地面・餌などの 3D 描画は表示しない
- 濃淡のスケール、ガンマ、セル間の隙間、配置（腹側を縦長に置くか横長に置くか）は切り替え可能にする
- HP を小さく別枠で表示
- **デバッグ表示切替**（必須）: 「本体ビュー」「触覚グリッド」「両方」を コントローラのボタン 1 つで切り替える。人間が「この濃淡なら歩けている／餌と害が見分けられている」を目で判断するための機能で、受け入れ判定はこれで行う

## 8. 記録

- 30 Hz で以下を同期記録: 触覚フレーム（全セルの輝度）、各節の目標角、実際の関節角、HP、頭部のワールド位置・向き（記録のみ。表示しない）
- 形式は後段の学習で読みやすいもの（CSV または npz など）。1 セッション 1 ファイル
- セッション開始時の環境配置（餌・害・障害物の位置）も保存

## 9. 受け入れの考え方

数値の閾値は事前に決めない（決めるだけの知見がまだ無い）。代わりに、以下を人間がデバッグ表示で目視して判断する。

1. 触覚グリッドだけを見て、地面・餌・害・障害物を見分けられるか
2. 触覚グリッドだけを見て、前進する周期運動を作れるか
3. 触覚グリッドだけを見て、障害物に当たったことに気付き、頭を曲げて回避できるか

見分けられなければ、第 5 節の材質パラメータや第 7 節の表示スケールを調整する。

## 10. 実装環境の希望

- Unity 6 + URP + Meta XR SDK を第一候補とする（既存の Quest 3 開発環境がある）。別の選択が明確に優れる場合は理由を添えて提案してほしい
- 最初は 2D 簡易版（Python 等）で触覚パターン生成と表示だけ先に検証する案も可。その場合は Unity 版との分担を示すこと

## 11. 依頼する成果物

1. システム構成図（身体・触覚モデル・環境・操作・表示・記録の分担）
2. 触覚応答モデルと材質パラメータの定義（後で実機値に差し替え可能な形）
3. コントローラ割り当ての比較案（第 6 節）
4. 実装手順。手順のうち Claude Code に任せられる部分は、手作業の指示ではなく Claude Code への依頼文として書く。ただし依頼文の作成は私が許可したときだけ行い、毎回勝手に出さないこと

## 12. 後段との接続（参考）

このシステムで集めた「触覚フレーム＋目標角」の時系列を、節ごとの NCA セルに与えて歩行を模倣学習させ、その後 HP（生存時間）を報酬にして磨く予定。隣接セル間の通信チャネル数（4〜8 想定）と 30 Hz の更新周期は、そのまま実機のマイコン間通信仕様になる。
